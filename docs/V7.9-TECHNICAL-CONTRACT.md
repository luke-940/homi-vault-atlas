# v7.9 Technical Contract

## Preserved renderer boundary

- The v7.8 Three.js scene, node geometry, colors, light, camera bookmarks, and
  stable hover behavior are frozen unless a verified defect requires repair.
- React owns Map Console, dossier, Reader, workbench, Search, URL state, and
  accessibility.
- Three.js owns the existing spatial graph only.
- Canvas2D remains the mobile and WebGL-failure sibling.
- Dossier tab changes and source reading do not rebuild or reposition the graph.

## Runtime packages

Initial data packs remain `graph`, `inventory`, `agency`, `meaning`,
`publication`, and a compact `knowledge` index. Dossier/Reader shards and the
search index are content-hashed scripts loaded on demand so `file://`, local
HTTP, and GitHub Pages share one path.

`KnowledgeProvider` is separate from the graph provider. It owns:

- shard request, cache, digest verification, loading, error, and retry state;
- active dossier tab;
- exact Reader document and section;
- lazy search index;
- safe non-release status for unreviewed Gate 1 nodes.

Hover reads only the compact index. It must not fetch a shard, commit a URL,
move the camera, or rerender the spatial scene.

## Canonical URLs

- `#home?focus=<nodeId>&panel=dossier&tab=overview|relations|evidence`
- `#explore?focus=<nodeId>&panel=dossier&tab=...&view=graph|structure|list`
- `#read?node=<nodeId>&section=<sectionId>`
- `#observe?mode=node&focus=<nodeId>`
- `#observe?mode=relation&from=<sourceId>&to=<targetId>`
- `#observe?mode=evidence&focus=<nodeId>&claim=<claimId>`

Reader navigation stores the originating semantic route and camera bookmark in
history state. Back restores the source workspace, committed focus, and camera.
Preview never enters the URL.

## Build-only content pipeline

1. stable double-read capture;
2. publication policy v3 document admission;
3. deterministic Markdown section/block parse;
4. section classification and public-safe block projection;
5. section-aware wikilink occurrence resolution;
6. graph aggregation from published occurrences;
7. reviewed dossier claim/evidence validation;
8. per-node shard and lazy search-index creation;
9. publication binding and privacy audit.

Raw Markdown, frontmatter, absolute paths, source hashes, or source filenames
must not be copied into runtime bytes.

## Gate 1 versus release

`build:gate1` writes a non-release output and requires the five reviewed sample
documents. `audit:gate1` may return `pass_gate1_nonrelease` only when it proves
`releaseEligible: false` and the exact reviewed set.

The normal `build`, `audit`, CI, and release commands remain strict: every graph
node needs a reviewed dossier and Reader. No environment flag may silently turn
a release build into a slice.

## Budgets

- initial transfer: 3.0 MiB hard limit;
- compact knowledge index: 220 KiB raw;
- lazy search index: 800 KiB gzip;
- one dossier + Reader shard: 180 KiB raw;
- shell: 180 KiB gzip;
- semantic-space: 240 KiB gzip;
- knowledge-workbench: 80 KiB gzip;
- total executable JS: 400 KiB gzip;
- minified CSS: 44 KiB target, 48 KiB hard limit;
- complete public artifact: 15 MiB target.

Initial HTML and scripts contain no dossier or Reader body.
